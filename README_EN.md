# Telegram File Transfer Bot

[中文](README.md) | English

Automatically download files received in Telegram and upload them to cloud storage. Built on Telethon (MTProto).

## Features

- **Large files**: Uses MTProto, up to 2GB per file; files over 10MB are downloaded with multiple parallel connections.
- **Multi-cloud**: Supports 70+ backends via rclone (OneDrive, Google Drive, Dropbox, S3, WebDAV, and more).
- **Multiple sources**: Send files in a DM, forward files, reply to a file message and mention the bot in a group, or listen to a channel and auto-download new posts.
- **One-click OAuth**: 20 OAuth cloud drives (OneDrive, Google Drive, etc.) use rclone's built-in app authorization — no need to register your own app or fill in client_id / secret.
- **Resume**: rclone uploads come with resume and automatic retries; if it fails, tap the retry button to send it again.
- **Timezone**: Each user can set their own timezone with `/timezone`.
- **Whitelist**: Only whitelisted users can use the bot.

## Requirements

- Python 3.10+
- rclone (verified 1.76)
- Telegram API credentials (api_id, api_hash)
- A Telegram bot (created via @BotFather)

## Quick Start

```bash
git clone https://github.com/longli928/telegram_bot_to_rclone.git
cd telegram_bot_to_rclone
pip install -r requirements.txt
cp .env.example .env
# Fill in .env
rclone config providers > providers.json
python app.py
```

Run in the background:

```bash
nohup python3 -u app.py > bot.log 2>&1 &
```

When you see `Bot 已上线` (Bot is online), it's running.

## Configuration

Fill in `.env`:

| Variable | Description |
| --- | --- |
| `API_ID` | Telegram app api_id |
| `API_HASH` | Telegram app api_hash |
| `BOT_TOKEN` | Bot token |
| `ALLOWED_USER_IDS` | Telegram user IDs allowed to use this bot, comma-separated; required — if empty, nobody can use it |
| `PARALLEL_CONNECTIONS` | Number of parallel download connections for files over 10MB, default 6 |
| `MAX_CONCURRENT_FILES` | Max number of files processed at the same time, default 5; 0 means no limit |
| `TIMEZONE` | Default timezone for users who haven't set one, default Asia/Shanghai |
| `DOWNLOAD_DIR` | Temporary download directory, default ./downloads |

## Usage

### Direct Messages

Send a file or forward a file to the bot; it downloads it and uploads it to the default storage (or the one you choose).

### Groups

Add the bot to a group, reply to a message with a file and mention the bot — it will download it. Only whitelisted users can trigger it, and the bot only responds to @mentions in groups.

### Channels

1. Add the bot to the channel as an admin.
2. In a DM with the bot, use `/channels` and forward a channel message (or send the channel @username / ID) to add it to the whitelist.
3. Files in new posts from that channel will then be downloaded and uploaded automatically, with progress sent to your DM.

### Commands

| Command | Description |
| --- | --- |
| `/start` | Start |
| `/help` | Help |
| `/storage` | Storage management (add / set default / change folder / delete) |
| `/channels` | Channel management (whitelist) |
| `/timezone` | View or set timezone |

### Storage Management

In `/storage` you can:

- **Add storage**: Pick from all rclone backends. OAuth drives (OneDrive, Google Drive, etc.) don't need client_id / secret — the bot sends you a login link; log in, then send the localhost link back to the bot. For non-OAuth backends, follow the prompts to fill in the parameters.
- **Import**: Register a remote that already exists in your rclone config.
- **Set default storage**: With a default set, files go straight there; with no default and multiple storages, the bot asks which one to use after each download.
- **Change folder**: Change a storage's folder without re-adding it.
- **Delete storage**: Removes the entry from the registry and the remote from the rclone config; files in the cloud are untouched.

## Security

- Only users in the `ALLOWED_USER_IDS` whitelist can use the bot; if empty, nobody can.
- Cloud credentials live only in rclone's own config file (`~/.config/rclone/rclone.conf`); the bot doesn't keep a separate copy. `storages.json`, `channels.json`, and `timezones.json` are all chmod 600.
- Secrets sent in chat while adding a storage are deleted by the bot after reading and never logged; tokens never appear in logs.
- Don't commit `.env` to a public repository.

## FAQ

**What is `providers.json`?**

The rclone backend list, used by the `/storage` add menu. Generate it with `rclone config providers > providers.json`; regenerate it after upgrading rclone. Without this file, the bot only offers 5 built-in backends (OneDrive, Google Drive, Dropbox, S3, WebDAV).

**The localhost link I pasted back for OAuth login failed?**

If the link has a problem (no code, no state, mismatched state, or the replay gets no code), the bot tells you what's wrong and ends the add flow. Make sure to paste the link from the latest message — an old link's state won't match.

**Files in a channel aren't auto-downloading?**

First confirm the bot has been added to the channel as an admin, and the channel is in the `/channels` whitelist.
